# T3 transcription
Paths: lib/transcribe/**, lib/keys.ts (read only unless a helper is missing), tests. Brief: docs/BRIEF.md lines 21-26.
- `transcribeChunk(chunk, settings, key)`: POST multipart to `${baseUrl}/audio/transcriptions` (file, model,
  response_format 'json', language 'en' unless settings.language is 'auto'); returns text. Groq or OpenAI per settings.
- Queue (`enqueue(chunkId)`, `drain(meetingId?)`, `catchUp()`): one request at a time, ≤20 requests/min (token
  bucket). On success write a Segment, set the chunk done, delete its audio, send `segment/added`. Empty text → no
  segment. On 429: read `retry-after`, set `connection/state` rate-limited with retryAt, keep chunks pending, retry
  after. 401/403 → reason 'auth', stop retrying until `transcription/catch-up`. Network error/offline → 'offline',
  retry with backoff (max 60 s), listen for `online`. 5xx → 'server', backoff. After 5 failed attempts mark failed.
  Send `connection/state {ok:true}` when a request succeeds after a failure. Send `transcription/drained` when no
  pending chunks remain for a meeting whose status is processing.
- Keys come from `loadKeys()` (lib/keys.ts) using `PROVIDERS[provider].keyName`; missing key → reason 'auth'.
- All fetch calls injectable for tests; tests cover success, 429 with retry-after, 401, offline backoff, ordering.
