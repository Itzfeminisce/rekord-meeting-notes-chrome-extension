# T2 audio capture
Paths: entrypoints/background.ts, entrypoints/offscreen/**, lib/audio/**, wxt.config.ts (manifest), tests.
Brief: docs/BRIEF.md lines 12 and 21-24.
- Background handles `recording/start {tabId}`: creates the Meeting (status recording, title = tab title), gets a stream
  id with `chrome.tabCapture.getMediaStreamId({ targetTabId })`, creates the offscreen document (reasons USER_MEDIA,
  AUDIO_PLAYBACK) if absent, sends `offscreen/start`. Broadcasts `recording/state`; answers `recording/get-state`.
  `recording/stop` → `offscreen/stop`, sets meeting status processing, endedAt. The side panel is opened by the action
  click, which grants tabCapture for the active tab; if it fails, fail with a clear error state, not a crash.
- Offscreen: tab stream via getUserMedia chromeMediaSource 'tab'; mic via getUserMedia({audio:true}). Route the tab
  audio back to the speakers (AudioContext destination) so the user still hears the meeting.
- Two MediaRecorders (one per speaker: tab = 'others', mic = 'you'), restarted every 10 s so each chunk is a standalone
  playable file (do not use timeslice fragments). Save each as a Chunk (status pending) in IndexedDB via lib/db.
- Silence: measure RMS with an AnalyserNode per stream during the chunk; if the chunk never exceeds a threshold, save it
  with status 'silent' and no audio. Post `offscreen/levels` about 4×/s (0..1).
- After saving a pending chunk, call the transcriber entry point `enqueue(chunkId)` from lib/transcribe (T3 builds it;
  for now import a stub `lib/transcribe/index.ts` exporting `enqueue` and `drain` no-ops if it does not exist).
- On stop: flush the last partial chunks (≥1 s, else drop), stop tracks, keep the offscreen document alive until the
  transcriber reports `transcription/drained`, then close it.
- Manifest: permissions add tabCapture, offscreen; keep host permissions minimal. Unit-test chunk timing/silence logic
  in lib/audio with fakes (no real media in tests).
