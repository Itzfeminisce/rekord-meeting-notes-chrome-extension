# T5 Diarize with Deepgram + suggest names
Frame: design/frames/Processing.dc.html (one added step). Paths: lib/diarize.ts, lib/speakers.ts,
screens/Processing.tsx (step + routing only), tests.
- `diarize(meetingId, fetchFn?)`: concat parts into one Blob; POST
  `https://api.deepgram.com/v1/listen?model=nova-3&diarize=true&utterances=true&punctuate=true&language=<en|multi>`
  with `Authorization: Token <DEEPGRAM_API_KEY>` and the blob's Content-Type.
- Map: convert each utterance's start/end to meeting time (add earlier pauses). For each 'others' segment pick the
  Deepgram speaker with the most overlap; ≥30% overlap or leave unlabeled. Relabel speakers 0,1,... → 'A','B',...
  by first appearance. Save `speakerLabel` on segments and `meeting.speakers` = {A: {}, B: {}}.
- One distinct speaker → label it 'A' still (screen asks for one name).
- `suggestNames(meetingId)`: `chat` (json) over `transcriptLines` with labels; ask per label for `{name, evidenceAtMs}`
  only when a name is clearly addressed to or used by that speaker; else null. Store as `suggested`/`evidenceMs`.
- Processing: after the summary, if `speakerStep 'pending'` run diarize → suggestNames with step "Telling voices
  apart" (`speakers/progress`); then `ready` → Speakers screen, else Summary. Any error → `failed`, keep You/Others,
  go to Summary; Summary shows "Couldn't tell voices apart. Try again" (retry runs T5 again).
- Tests: request shape (fake key), overlap mapping incl. pauses, relabel order, name parsing, failure path.
