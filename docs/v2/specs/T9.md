Bug (field test): "Others · This tab" fails with "Rekord couldn’t start recording…". `tabCapture.getMediaStreamId`
needs the extension to be invoked on that tab (activeTab grant). With `setPanelBehavior({openPanelOnActionClick:true})`
the icon click opens the panel but `action.onClicked` never fires, so the meeting tab is most likely never granted.
Mic-only works.

  `browser.sidePanel.open({ tabId: tab.id })` synchronously inside the listener (it must stay in the user gesture; no
  awaits before it). The click grants activeTab for that tab. Keep the mutex/persisted state untouched.
- Refused capture: log Chrome's message; reply with the copy
  "Click the Rekord icon in the toolbar while you’re on the meeting tab, then press Start." (curly apostrophe).

  tab is granted (no "tabs" permission; host_permissions don't cover meeting sites). When "Others" is ticked and the url
  is missing, show that same hint above Start recording (not an error; still let them press Start). Re-check when the
  active tab changes (tabs.onActivated / onUpdated) and on panel focus. Mic-only never shows it.
- Tests: helper that decides the hint (`needsTabGrant({tabOn, tabUrl})`), and the refusal reply copy.
