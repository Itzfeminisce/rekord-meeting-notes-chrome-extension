# T4 Real-time transcription with Deepgram, backup to Groq
Frames: V3Live, V3States "Live · real time stopped, backup on". Rows: FRAMES.md V3Live.
Paths: lib/transcribe/stream.ts (new), entrypoints/offscreen/main.ts, entrypoints/background.ts (token mint),
screens/Live.tsx, lib/speakers.ts (skip post-meeting diarization when realtime), tests.
- First verify Deepgram's current docs: grant endpoint `POST https://api.deepgram.com/v1/auth/grant`
  (`Authorization: Token <key>`, returns a short-lived JWT) and browser WebSocket auth via subprotocol
  `['bearer', jwt]`. If either differs, adapt and note it in the log line.
- When settings.transcription.provider is 'deepgram': open two sockets (mic → "You", no diarize; others →
  `diarize=true`), `model=nova-3`, `interim_results=true`, `smart_format=true`, language per settings, encoding
  matching the recorder (or PCM via AudioWorklet if webm/opus isn't accepted). Mint a fresh token per connection.
- Interim results render as the greyed line with a caret (not stored); finals become Segments with speakerLabel.
  Status line "Transcribing as people speak" and "<n> people talking" from distinct live speakers.
- Keep the v1 chunk recorder running. Socket drop or error: if realtimeBackup, emit `stream/state: backup`, show the
  banner, transcribe chunks from the drop time with Groq so nothing is missed, retry the socket every 30 s and on
  "Try real time again"; on success switch back without duplicating text. realtimeBackup off: show the v2
  connection-lost banner.
- Meeting.realtime = true → the v2 Deepgram post-meeting pass is skipped; names step uses live labels.
- Tests: token request shape (fake key), interim/final handling, drop → backup → recover without gaps or duplicates.
