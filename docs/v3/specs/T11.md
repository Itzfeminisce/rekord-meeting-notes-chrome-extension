# T11 Connect Penv Cloud with one click (starts when Penv Cloud app connections are live)
Frames: V3PenvConnect, V3PenvConnected, V3SettingsAI (key source row, "Manage on Penv Cloud", "Disconnect"),
V3States "Setup · Penv Cloud not connected", "Setup · Penv Cloud shared no usable keys",
"Start or Settings · Penv Cloud disconnected". Rows: docs/v3/FRAMES.md for those.
Server side: Penv Cloud "App connections" (OAuth 2.0 code + PKCE). Routes: `https://penv.cloud/connect`,
`POST /api/v1/auth/app/token`, `POST /api/v1/auth/app`, `POST /api/v1/auth/revoke`, existing `GET /api/v1/envs/...`.
Paths: lib/penvApp.ts (new), lib/connect.ts (key source 'penv-app'), screens/Setup.tsx + SettingsAI.tsx (wire the
button and states T2 laid out), entrypoints/background.ts (exchange on key load), tests.
- Precondition: Rekord is registered on Penv Cloud with redirect `https://<extension-id>.chromiumapp.org/penv`
  (fixed ID from T1). No flag: `penvAppAvailable()` POSTs `{}` to the token route; 404/offline hides the button.
- Connect: `chrome.identity.launchWebAuthFlow({ url, interactive: true })` with client_id `rekord`, PKCE S256,
  random state, `keys=` the names the chosen preset needs plus optional DEEPGRAM_API_KEY and NOTION_TOKEN.
  Verify state; exchange the code; store the `pca_` grant in `chrome.storage.session` with the other secrets
  (and, only if the owner approves later, nowhere else). Show V3PenvConnected with the shared key rows.
- Load keys: exchange grant → `pck_` (store the rotated grant), read the env, keep keys in memory as today.
  `invalid_grant` → clear and show "Penv Cloud disconnected". Window closed or `access_denied` → "not connected".
  Shared keys missing what the preset needs → "shared no usable keys" with "Change which keys" (relaunches connect).
- Disconnect: `POST /api/v1/auth/revoke` with the grant as bearer, clear keys, back to Setup.
- "Use a token instead" keeps the v1/T2 token path working.
- Tests: PKCE pair and URL, state mismatch, exchange + rotation, invalid_grant, cancel, missing keys, disconnect.
- Server contract (verified against the Penv Cloud source):
  - `/connect?client_id=rekord&redirect_uri&state&code_challenge&code_challenge_method=S256&keys=a,b[&env_hint]`; no
    `scope`/`response_type`. Keys `^[A-Za-z0-9_][A-Za-z0-9_./-]{0,254}$`, max 100. Back: `code`+`state` or `error`.
  - `POST /auth/app/token` `{client_id, code, code_verifier, redirect_uri}` → 201 `{grant: pca_, connection:{id, org,
    project, environment, keys}}`. 400 invalid_grant → retry connect; invalid_client/invalid_redirect_uri → not connected.
  - `POST /auth/app` `{grant}` in the body, no Authorization → 201 `{credential: pck_, expiresAt, grant}` (rotated; store
    it before use, a replayed grant revokes the connection). 400 invalid_grant → disconnected. 429 rate_limited → retry.
  - `GET /envs/{org}/{project}/{environment}` with Bearer pck_ → `{keys:[{name, value} | {name, redacted:true}]}`;
    the app path skips redacted entries. `POST /auth/revoke` Bearer pca_, no body → 204.
